# 拾音 · 滚动歌词 MV 生成器

中文 Windows 开源应用，采用 **WPF + WebView2**。导入音乐文件，读取封面并匹配时间轴歌词，选择背景视频，然后生成旋转黑胶唱片与自动滚动歌词组成的视频。

## 使用

启动时显示黑胶旋转、拾音标识与加载光点，界面准备好后淡入创作工作台；遵循 Windows 的减少动画设置。启动页支持拖动窗口和关闭，启动过渡有超时兜底。

从 [GitHub Releases](https://github.com/chenziren912/shiyin/releases/latest) 下载 `拾音安装程序-0.9.0.exe`。安装包使用 Inno Setup 打包，安装界面与应用界面均为中文，安装目录可修改。构建脚本强制检查安装包 **≤ 50,000,000 字节**，不会生成分卷、MSI 或 ZIP 分发包。

1. 安装并启动程序。现有 .NET 10 桌面运行时和 WebView2 会被复用；缺失时联网准备。缺失的 .NET 以私有运行环境保存到安装目录的 `runtime` 文件夹，不要求把它打进 EXE。
2. 程序检测本机 FFmpeg / ffprobe 与 Python 3.9+。缺失时点击“确定，下载并安装”，才开始下载。FFmpeg 使用 gyan.dev 最新正式版 essentials 构建；Python 使用 python.org 上 3.14 系列最新可用的 64 位正式安装包。渲染器没有 pip 依赖。
3. 选择音乐文件。读取歌名、歌手、专辑、时长及内嵌封面，兼容格式标签和音频流标签。优先读取同名 LRC 和内嵌歌词，其次查询 [LRCLIB](https://lrclib.net/docs)。在线服务不需要密钥，无法保证收录所有歌曲，也不提供音频指纹识曲。可修改关键词、选择不同录音版本，或导入 UTF-8 / GBK 的 LRC。
4. 选择背景视频，或使用默认纯色。背景短于歌曲时循环，背景自带音轨不混入成片。封面可以单独更换。
5. 调整音乐音量 **0–1000%**、背景亮度 **0–100%**、字幕大小、输出目录和文件名，然后生成。支持 480P / 720P / 1080P，24 / 30 / 60 帧。在“编码设置”中选择文件格式、视频与音频编码。超过 100% 的音量启用峰值限制器。

歌词窗口支持编辑 LRC 和整体 ±60 秒时间偏移；设置中可以调整默认字幕大小。空白的带时间戳歌词行可用来表示间奏。纯音乐模式无需歌词。普通纯文本歌词不会被伪造成精确时间轴。

偏好设置中的“软件主题色”提供青苔绿、湖水青、晴空蓝、靛青蓝、鸢尾紫、樱花粉、琥珀金、珊瑚橙、朱砂红和石墨灰，共 10 种。点击色卡立即应用并自动保存，也可用方向键切换。按钮、面板、进度条、弹窗、启动动效和更多设置窗口使用统一配色，重启后恢复选择；主题保存到 `%LOCALAPPDATA%\VinylMV\software-theme.json`，网页缓存用于启动前的配色。视频预览和实际导出继续使用画面卡片中的独立颜色配置。

音乐选择器支持 MP3、WAV、FLAC、M4A（含 AAC / ALAC）、AAC、OGG、Opus、WMA、AIF / AIFF、APE、WV、ALAC、AC3、DTS、MKA、MP2。背景选择器支持 MP4、MKV、WebM、MOV、AVI、M4V、WMV、FLV、TS、MTS、M2TS、MPG / MPEG、VOB、OGV、3GP、3G2、MXF。两者都提供“所有文件”入口，由 FFmpeg 检查实际媒体流；具体解码能力取决于安装的 FFmpeg 构建。

无法直接在 WebView2 播放的音乐或背景会自动准备兼容预览，显示处理提示并允许取消。预览副本缓存在本机，原文件路径、大小或修改时间变化后重新生成；卡片编辑器复用相同预览。实际导出和离线频谱分析始终读取原始素材。原始 AAC 等仅能估算时长的文件，在预览准备完成后校正时长。单首工作台与批量窗口均支持 MP4、MKV、MOV、WebM。

单首作品点击主工作台右侧“调整与导出”标题栏中的“编码设置”（位于“重置”左侧），直接打开分组的详细弹窗。下方保留当前编码摘要。视频提供 H.264、H.265、AV1、VP9、VP8、ProRes、FFV1；音频提供 AAC、Opus、MP3、FLAC、ALAC、16 / 24 位 PCM、Vorbis。提供处理器软件编码及英伟达 NVENC、英特尔 QSV、AMD AMF；具体可用编码器取决于本机 FFmpeg、显卡与驱动。打开弹窗时读取本机编码器列表，并实际编码短帧验证硬件；不可用硬件不能应用，可在更新驱动后重新检测。能力按 FFmpeg 路径、大小和修改时间缓存；软件编码可用性表示本机编译包含该编码器。

参数按编码类型联动，包括恒定画质、动态平均码率、固定目标码率、目标与峰值码率、缓冲、速度、规格、8 / 10 位像素格式、画面调优、关键帧、预测帧、线程、音频码率、采样率、声道与快速起播。ProRes 使用自身规格，FFV1 提供版本与分片校验；无损音频不显示码率。NVENC 额外提供前瞻帧、空间自适应量化、多遍分析。AV1 软件编码支持画质和平均码率模式，平均码率模式不提供峰值限制；不同编码器的画质数值不可直接比较，速度预设映射到各自参数。Opus 固定 48 kHz，单声道最高 256 kbps；MP3 最高 320 kbps、48 kHz。Vorbis 使用 0–10 的独立音质参数控制可变码率。输出 10 位不代表 HDR，无损编码也不会恢复输入已经丢失的信息。参数依据 [FFmpeg 官方编码文档](https://ffmpeg.org/ffmpeg-codecs.html) 与本机编码器帮助实现。

不兼容的容器与编码组合会禁用，后端也检查兼容性。WebM 可选择 AV1 / VP9 / VP8 与 Opus / Vorbis；ProRes 使用 MOV 或 MKV，FFV1 使用 MKV。更改容器时，如果原编码无法使用，会在界面切换成兼容选项。单首在编码弹窗点击“应用设置”即保存到本机，并用于后续生成，文件名后缀和编码摘要同步更新；取消弹窗丢弃本次编码草稿。“更多设置”负责画面卡片编辑，应用或取消画面调整均不会覆盖已保存的编码。批量导出保留其窗口内的“详细编码设置”入口和独立偏好。默认仍为 MP4、H.264 软件编码、恒定画质 20、很快、AAC 256 kbps。指定有损音频和视频码率时估算文件大小，实际大小取决于素材与编码器。

点击预览右上角的“更多设置”打开独立的卡片编辑窗口。左侧是大尺寸静态帧预览，拖动下方时间轴可以查看其他时刻；编辑器不会播放音视频。黑胶、歌曲信息、歌词、时间、播放进度条和音频曲线均可拖动、缩放、删除和恢复，支持撤销、重做及方向键微调。

双击卡片打开详细编辑，可调整黑胶封面直径比例与旋转速度、歌词字号及行距和颜色、歌名歌手文字、时间格式和圆角底色、进度条颜色和粗细、曲线颜色和动态幅度。曲线默认与进度条共用起点和基线，也可单独移动。点击“应用到作品”后同步到主预览、保存到本机偏好并用于实际导出；点击“取消”会保留原配置。

歌词卡片默认开启“随背景自动配色”：每半秒采样歌词所在区域，结合背景亮度、遮罩与色调，选择对比度更高的柔和颜色，同时调整当前行、相邻行、其他行及描边颜色。背景循环时重新应用对应配色；关闭该选项后使用手动颜色。预览和导出采用相同的配色算法，采样与分析均在本机完成。对比计算参考 [W3C 相对亮度定义](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance)。

音频曲线卡片新增“平滑曲线 / 上下镜像曲线 / 柱状图”。三种样式均可调整 16–192 个频段、512 / 1024 / 2048 / 4096 点 FFT 采样精度、空间平滑度、上升和回落响应、分析频率范围与动态幅度；曲线可调粗细，柱状图可调柱间留白。频段数决定控制点或柱子的数量，FFT 长度决定频率分辨率，两者可以分别调整。镜像曲线关联进度条时整体放在进度条上方；默认单曲线仍保持原有共同起点与基线。静态预览只分析所选时刻的音频，不播放声音，配置同时用于单首与批量成片。FFT 参数依据 [Web Audio 分析节点规范](https://www.w3.org/TR/webaudio/#dom-analysernode-fftsize)。

左侧唱片随播放旋转，封面印在唱片中心；右侧歌词按时间轴滚动，歌词栏加宽至画面宽度的 55%，英文按完整单词换行，超长句适当缩小字号；画面下方显示播放进度，右上角显示已播放 / 总时长。可开启跟随实际音频频谱的可视化，默认平滑曲线的起点及静止基线与底部进度条重合，波峰向上起伏；暂停预览时可视化停止。预览与导出均不显示左上角的静态标语。导出使用相同布局，字体由 Windows 本机字体渲染，因此浏览器预览和成片字形可能存在细微差异。

导入的音视频文件由本机处理；歌词请求仅包含歌曲标签和用户输入的关键词。可选 AI 背景功能将提示词交给配置的远程服务，详见下文。依赖及缓存位于 `%LOCALAPPDATA%\VinylMV`，不修改系统 PATH。开始生成前检查渲染组件完整性，并将完整的 Python 渲染组件快照到任务目录，避免后续安装目录变化影响正在生成的任务。完成输出采用临时文件后重命名，取消不会留下一个伪装成完整作品的 MP4，同名输出自动增加序号。

## 批量导出

点击左侧“批量导出”，在“视频库”中一次导入多个背景视频，为每个视频填写适合的音乐风格。风格支持多标签和自定义文字，例如“流行, 民谣”；也支持选择多条视频后统一设置。视频库保存在 `%LOCALAPPDATA%\VinylMV\video-library.json`，移除条目保留原视频文件。已缺失的视频会标记并排除出随机池。

批量导入音乐或视频时，进度条按已处理文件数推进，并显示数量及百分比；文字中的“正在读取第几项”表示当前处理对象。重复路径先去重，损坏文件也计入已处理数量并另外提示错误。准备兼容预览时保留总进度；单文件无法确定处理百分比时显示加载动画。取消会保留已导入项目，下一批从零开始。

在音乐队列中一次选择多首歌，优先读取歌曲的 genre 标签，可逐首或选中多首后修改。Pop、Rock、Jazz 等常见英文风格会与对应中文风格匹配。默认从匹配风格的视频中随机选一个；无匹配或无风格标签时，使用全部可用视频。队列显示分配结果和匹配来源，可以重新分配。调整导出格式或命名时保留当前背景分配。

批量窗口右上角“导出设置”打开独立弹窗。背景可选择优先匹配音乐风格或使用全部可用视频，按随机或视频库顺序循环分配；可优先使用本次队列中分配次数较少的视频。减少重复始终遵循候选范围，候选视频不足时允许复用。无匹配风格时可回退全库，或暂不分配、等待调整。修改背景策略后重新分配未完成任务，已完成任务保留；未开启 AI 背景时，未分配背景的选中任务会阻止开始导出，并提示原因。

右侧可设置统一输出目录、文件命名模板、MP4 / MKV / MOV / WebM、分辨率、帧率和详细编码，再点击“应用到选中任务”。新导入音乐使用当前设置，已有任务也可逐首修改文件名与格式。命名支持 `{序号}`、`{歌名}`、`{歌手}`、`{原文件名}`、`{风格}`。批量编码偏好与单首独立保存，各任务保留应用时的编码配置；逐首改变文件格式时，如果原编码不兼容会改用兼容组合，列表显示实际采用的编码摘要。

画面样式、音量、亮度及字号在开始时从主工作台复制；每首歌使用自己的封面、歌名、歌手和同名 LRC。“导出设置”中可选择是否在线搜索缺失歌词；仍没有可用时间轴歌词时，可让歌词区域留空、显示自定义固定文字或跳过音乐。固定文字默认“该歌曲暂无可用歌词”，支持最多 300 字及换行，整首静态显示并沿用歌词卡片的字号、位置、对齐和配色，删除歌词卡片后不会显示。歌词留空模式不再显示默认纯音乐提示；单首生成保留原有纯音乐提示。

弹窗同时提供“单首失败后继续”，关闭后首次失败会停止新增任务，已经运行的任务继续完成；按歌词策略跳过不计为失败。点击“应用设置”才保存，取消或按 Esc 丢弃草稿，恢复默认也需要应用。旧版批量偏好会保留原来的歌词与错误处理选择。队列支持智能并发、重试失败任务及停止整个队列。停止会保留已完成作品，同名输出增加序号；多个任务同时导出同名文件时也不会互相覆盖。视频库与批量偏好跨启动保存，任务队列和本次导出结果在当前程序会话中保留。

首次运行且依赖就绪时，询问是否检测设备以优化导出。选择“暂不检测”后不会在每次启动时重复询问，也不会自动测速；之后可从偏好设置的“设备与编码性能”，或批量导出设置中的“设备信息与编码测速”开启。检测无需管理员权限，读取 CPU 型号、逻辑处理器数、GPU 型号与驱动信息，并显示 FFmpeg 提供的软件编码器和实际短帧验证可用的硬件编码器。

设备窗口可以选择文件格式、分辨率、帧率、并发上限，打开完整的编码参数弹窗设置码率模式、目标码率、画质、速度等条件。使用三秒合成音频与画面，按当前画面中的音频可视化配置执行真实音频解码、FFT、频段平滑与曲线绘制指令生成，再将曲线实际合成到视频，依次尝试 CPU 软件编码及当前格式支持的英伟达 NVENC、英特尔 QSV、AMD AMF。平滑曲线、上下镜像与柱状图均使用实际导出的分析和绘图代码，沿用当前频段数、FFT 精度、平滑度、布局等设置；关闭音频曲线时跳过分析。结果分别记录曲线分析、合成编码与合计耗时，以包含分析开销的综合帧率自动选择；同一份分析耗时计入各编码器以保持比较条件一致。测试使用真实容器和音频编码，参数不兼容时不擅自降低画质或修改格式。不同编码器的相同画质数值不保证相同画质；完整 MV 仍受背景与其他卡片影响，短片测速不等于完整作品耗时保证，建议设备空闲时重新测速。

批量导出设置中默认开启“根据实测性能自动选择 CPU / GPU 编码”。同意检测后，导出前为缺少记录的参数组补充测速；同样的容器、分辨率、帧率、码率、速度、音频曲线开关、类型、采样精度、频段与布局等参数会复用记录。改变音频可视化设置后重新匹配；0.7.0 的纯编码测速记录自动失效。设备、驱动或 FFmpeg 文件指纹变化后重新匹配测速；无法读取设备清单时不跨进程复用旧设备记录。首次选择最快的可用编码器，后续新增任务参考实时负载；保留用户选择的编码格式与码率。关闭自动选择或未同意检测时，使用原有手动编码设置。已验证硬件编码在实际任务中失败时，若有通过同参数测速的 CPU 候选，则自动重试并提示回退。

默认最多同时运行 **3 个导出任务**，可在批量导出设置中改为 **1–16**；设为 1 即逐首导出。这是任务并发上限，独立于 FFmpeg 内部的编码线程数。设备测速时，编码线程数为自动的 CPU 配置按逻辑处理器数和并发上限分配，显式线程数保持不变。调度每隔约一秒采样负载，每次新增任务至少间隔约 1.5 秒。CPU 与候选 GPU 有空闲时逐步增加任务，优先选择占用较低的一侧；负载接近时参考实测速度。新增任务的占用上限默认 85%，可调为 50–95%。硬件编码时合成画面仍需要 CPU，因此 CPU 繁忙也会暂停新增 GPU 任务。

CPU 使用 Windows 系统时间差分，GPU 使用 [Windows 性能计数器](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw)，按物理引擎汇总进程占用后取最高值；多张 GPU 采用整体保守负载，不逐卡绑定。无法读取 CPU 占用时保守逐首运行，无法读取 GPU 占用时不继续叠加 GPU 会话，界面明确显示“不可读取”。队列显示活动任务数、等待数量、CPU / GPU 占用与每首实际使用的编码器。停止会终止全部活动任务并取消等待项；已经完成的作品保留。

也支持命令行批量导入：`VinylMV.exe --batch "D:\音乐\第一首.flac" "D:\音乐\第二首.mp3" --videos "D:\视频\湖面.mp4" "D:\视频\夜景.mkv"`。

开发验证：`dotnet run --project tests/CoreChecks/CoreChecks.csproj -c Release -- --batch` 检查分配、保存、命名、失败继续和取消；`python tests/test_containers.py` 实际导出额外容器。`python tests/prepare_batch.py` 生成合成素材后，用 `tests/start_ui_test.ps1 -Port 9235 -BatchFixture "素材目录"` 启动独立测试窗口，再通过 `VINYLMV_TEST_PORT=9235` 执行 `node tests/batch_smoke.mjs` 验证完整界面队列。

在另一独立测试窗口执行 `tests/batch_settings_smoke.mjs`，验证策略弹窗保存、取消、旧偏好迁移、顺序分配、严格匹配、保留完成任务以及固定文字 / 留空 / 跳过的实际导出。端口同样通过 `VINYLMV_TEST_PORT` 指定。

`dotnet run --project tests/CoreChecks/CoreChecks.csproj -c Release -- --device` 验证设备授权、实际编码测速与缓存、曲线设置缓存隔离、实时资源采样、并发上限、负载调度、硬件回退和三个真实同名导出。`python tests/test_device_benchmark.py` 检查对应格式、码率、分析与合成计时及不静默修改画质；加 `--integration` 实际测试平滑、镜像、柱状图与关闭曲线，保留成片、绘图指令和提帧。启动隔离测试程序时加 `-TestDevicePrompt` 可验证首次提示，再运行 `tests/device_smoke.mjs`；加 `--accept` 验证首次同意与停止。其他界面回归默认在隔离目录预设“暂不检测”，防止测速影响原有检查。

## AI 背景视频

在“批量导出”右上角打开“AI 背景视频”，填写 API 根地址、密钥和视频模型后开启。可为每首音乐生成背景，或仅在没有可用视频库背景时生成；生成失败可回退已有分配、跳过音乐或标记失败。每首生成一段短片，导出时循环铺满歌曲，成片继续使用所选音乐的音轨。

配置分为接口与策略、视频与画面、提示词设计、文字模型优化、运行与保存、高级接口六组。支持时长、尺寸、镜头、环境动感、视觉风格、情绪、场景、配色、负面提示词、首尾循环构图和按当前卡片位置预留清晰区域。音乐风格优先使用标签及批量列表中修改的风格。提示词可选中文或英文，可使用自定义模板，也可在队列中逐首编辑。只预览提示词不会创建视频任务；手写的单首提示词直接使用，不再自动润色。

可选使用独立的对话文字模型进一步润色提示词，支持模型、地址、独立或共用密钥、温度、输出词元上限及失败回退。歌词参考默认关闭；开启后仅发送限定长度的去时间戳歌词。接口接收文字信息和提示词，不上传原始音频。

提供两种协议：

- **Videos 标准接口**：按 [OpenAI 官方视频接口文档](https://developers.openai.com/api/docs/guides/video-generation) 使用表单提交、查询任务状态，再下载视频内容。默认路径为 `videos`、`videos/{id}`、`videos/{id}/content`；标准时长 4 / 8 / 12 秒，尺寸 1280×720、720×1280、1792×1024、1024×1792。模型是否可用由配置的服务决定。
- **通用 JSON 任务接口**：可自定义请求模板、创建 / 查询 / 下载路径及任务编号、状态、进度和结果 URL 字段。支持同步返回 URL 或异步任务；支持 `data.id`、`data[0].url`、JSON Pointer 和 `|` 分隔的候选路径。模板变量值保留数字、布尔及字符串类型；帧率、种子、生成声音等参数需要服务支持并在模板中引用。API 协议不一致时需要按该服务的文档调整，不能保证任意接口直接兼容。

AI 并发默认 2，可调 1–8，同时受批量导出总并发上限约束；支持查询间隔、任务总等待、单次网络超时、查询重试和下载大小上限。创建任务的 POST 不自动重发，查询限速与临时错误可重试。停止后保存已收到的任务编号，重试时优先继续查询；本地停止不会自动取消服务端任务，服务商可能继续生成并计费。

生成背景下载后通过 FFmpeg 检查，再交给 MV 渲染器。可选择保存目录、复用相同歌曲与参数的背景，并自动加入视频库及标注音乐风格。已生成文件保留，重新生成使用新文件名；只有下载中的临时文件在失败或停止时清理。配置与密钥通过 Windows 当前用户 DPAPI 加密保存到 `%LOCALAPPDATA%\VinylMV\ai-video-settings.dat`，密钥不写入网页偏好，也不随跨站下载重定向转发。

本地接口验证：先运行 `node tests/ai_video_fixture.mjs`，再将其输出的 `fixture.json` 路径传给 `dotnet run --project tests/CoreChecks -c Release -- --ai-video "路径"`。真实 WebView2 界面检查使用隔离批量测试窗口，指定 `VINYLMV_TEST_PORT` 与 `VINYLMV_TEST_APP` 后运行 `node tests/ai_video_smoke.mjs`，之后可运行 `node tests/ai_video_empty_library_smoke.mjs "素材目录"` 验证空视频库直接生成。两个界面脚本使用 `tests/prepare_batch.py` 创建的同一合成素材目录；这些验证使用本地模拟 API 和合成媒体，不调用付费视频服务。

## 自研下载器

实现位于 `src/VinylMV/Core/AdaptiveDownloader.cs`：

- 支持 HTTP Range 的服务器从最多 4 个并发工作线程开始，1 MiB 分段，直接写入不同文件偏移。
- 每 3 秒计算一次带宽；低于 **5,000,000 字节/秒**时增加一个线程。
- 每次增加后比较下一个测量窗口；增加量**不超过 200,000 字节/秒**计为一次无有效增速；连续 10 次后停止增加。出现有效增速则重新计数，线程上限 32。
- 严格验证 206 响应的 Content-Range 与文件长度；支持 ETag / Last-Modified 条件请求，分段最多尝试 3 次；取消会关闭请求并移除临时文件。
- 服务器不支持 Range 时使用单线程，界面明确显示原因。代理或服务器不支持分段时，增加线程无法突破该限制。
- FFmpeg 对照下载站点 SHA-256 校验；Python 安装包验证受信任的 Python Software Foundation 数字签名后执行。Python 安装事务开始后等待安装完成，再响应取消。

MB / KB 阈值使用十进制单位，分段大小使用二进制 MiB。

## 开发和打包

需要 Windows 10 2004+ / Windows 11 x64、.NET 10 SDK、Inno Setup 6.7+；只有重新生成图标时才需要开发机安装 Pillow。程序运行不需要 Node.js。

```powershell
dotnet build src\VinylMV\VinylMV.csproj -c Release
dotnet run --project src\VinylMV\VinylMV.csproj
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1
```

也可通过 `VinylMV.exe "D:\音乐\歌曲.mp3" --background "D:\视频\背景.mp4"` 直接打开素材，随后在界面中调整和生成。

可以使用 `tools\build.ps1 -Iscc 'C:\路径\ISCC.exe'` 指定编译器。构建脚本获取微软 .NET 发布元数据，用官方 SHA-512 验证运行时下载，生成安装器所需 SHA-256，并验证 WebView2 引导程序的微软数字签名。这些大体积运行时只用于校验和按需联网安装，不会加入安装包。打包完成后自动检查 50 MB 上限。

应用是 framework-dependent 发布；安装器交付为一个 EXE，安装后仍包含正常的 DLL、HTML、CSS、JS 和 Python 渲染源码文件。50 MB 指**分发安装包**，安装后的组件、缓存及视频文件所占空间会更大。

布局使用 16:9 画面的相对坐标，预览与 Python 渲染器分别校验同一套卡片配置。Windows 原生独立编辑窗口复用 WebView2 环境；新窗口在消息回调结束后打开，以遵循 [WebView2 线程模型](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/threading-model)。静态帧的音频曲线通过 FFmpeg 读取所选时刻前 0.3 秒的 PCM，再离线计算频谱，不播放音频。

```powershell
python tests\test_renderer.py
python tests\test_renderer.py --integration
python tests\test_encoding.py
python tests\test_encoding.py --integration
dotnet run --project tests\CoreChecks\CoreChecks.csproj -c Release
```

集成测试使用合成音乐与视频，不包含第三方歌曲。检查中文及特殊字符路径、封面合成、背景循环、1000% 音量、静音模式、输出编码与时长。核心检查使用本机临时 HTTP 服务验证并发分段、单线程回退、错误范围拒绝、取消与原文件保护。

编码集成测试实际导出 H.264 / H.265 与三种码率模式的六组组合，检查视频编码、AAC、采样率、声道、关键帧间隔和 MP4 索引位置。开发机还可通过 `tests/start_ui_test.ps1 -Port 9228` 启动独立的屏幕外验证窗口，设置 `VINYLMV_TEST_PORT=9228` 后执行 `node tests/encoding_smoke.mjs`；该检查需要 `.tools/ui-test` 中的 Playwright，仅操作隔离的合成素材与浏览器配置。

`python tests/media_formats.py` 生成 13 种音乐样例和 11 种视频样例，并输出样例目录。随后用 `dotnet run --project tests/CoreChecks/CoreChecks.csproj -c Release -- --formats "样例目录"` 检查信息读取、中文标签、封面、歌词、预览缓存、损坏输入和取消重试；`python tests/media_formats.py --render "样例目录"` 从四组原始素材执行带音频曲线的实际导出。界面测试启动器可通过 `-AudioPath` 和 `-BackgroundPath` 指定这些合成素材，再执行 `tests/formats_smoke.mjs` 验证 WebView2 播放、拖动、卡片编辑和原始素材导出。
